# AE2 线缆拓展

目标：Minecraft Java 1.21.1、NeoForge 21.1.169 或更高的 21.1.x、官方 AE2 **19.2.18**。这是 NeoForge 附属模组，不用于 Fabric。AE2 本身还需要 GuideME 21.1.1 或兼容的较新版本。

当前状态：初版源代码及资源已准备，静态资源检查通过；云环境尚未放行 `maven.neoforged.net`，构建在下载 NeoForm Runtime 时收到 HTTP 403。尚无经过编译和游戏验证的可安装 JAR，游戏测试尚未执行。待依赖网络恢复后继续构建、诊断和交付。

## 全覆盖范围

五种实际承载 AE2 频道的线缆：水晶（AE2 Glass）、包层、智能、致密包层、致密智能。每种覆盖无色 Fluix 和全部 16 种染色，每个组合有三级，共 **255 种组合**。

二级直接复用 AE2 原有的 85 个物品及 ID，新增一级和三级共 170 个物品。石英纤维仅传输能量，本身不是承载 ME 频道的线缆，不改变其行为。

| 类型 | 一级 | 二级（原版） | 三级 |
| --- | ---: | ---: | ---: |
| 水晶 / 包层 / 智能 | 4 | 8 | 16 |
| 致密包层 / 致密智能 | 16 | 32 | 64 |
| 名称稀有度 | 普通：白色 | 稀有：蓝色 | 史诗：紫色 |

频道数指 AE2 默认频道模式。线缆的染色仍控制网络连接；稀有度只改变物品名称颜色，不改变线缆的染色或纹理。

## 材料及配方

- 同类型、同颜色的 **1 根二级 → 4 根一级**，无序合成。每根一级恰为原材料成本的四分之一。
- 同类型、同颜色的 **4 根一级 → 1 根二级**，可恢复原版线缆。
- 同类型、同颜色的 **4 根二级 → 1 根三级**，材料成本为原版四倍。
- 无色一级水晶另有直接配方：与原版相同的 `1 石英纤维 + 2 福鲁伊克斯材料` 产出 16 根一级水晶线缆，原版该材料产出 4 根二级。
- 一级、三级都支持 `8 根同类型同等级线缆 + 1 份对应染料 → 8 根染色线缆`。
- 洗色沿用 AE2 的 `ae2:can_remove_color` 材料规则，输出保持原等级，不会变回二级。

共 426 个配方，全部使用附属自己的命名空间；不覆盖 AE2 原有合成配方。新增染色配方使用标准 `c:dyes/*` 染料标签，支持提供这些标签的其他模组染料。

一级通过批量拆分降低材料成本，不另外设计新的低阶材料体系；三级通过材料压缩实现成本提升。

## 网络及兼容设计

- 新物品创建 AE2 原有的线缆部件类，复用其网络节点、碰撞、部件宿主、侧面设备规则、智能灯、保存、拆卸和同步机制。
- 通过仅针对本附属新线缆的节点容量处理及相邻连接容量处理实现新上限。普通 AE2 设备、其他附属的自有节点和 AE2 二级线缆保留原容量。
- 原版二级物品通过 NeoForge 默认组件事件设置为蓝色 `RARE`，不注册替代的二级物品。
- AE2 的染色器和部件重染色操作会保留一级/三级身份；颜色互联及无色线缆行为仍使用 AE2 实现。
- AE2 的 x2、x3、x4 频道模式会按其倍率放大新线缆容量，无限频道模式继续无限。
- 保留无控制器网络的原版限制；三级线缆不会自动把无控制器网络升级成 16/64 频道网络。
- 高容量路径需要所有相关线缆都足够高级。混入一级或二级线缆仍形成容量瓶颈；P2P 隧道、机器等端点的原版限制没有被普遍提高。
- 智能线缆继续使用原有的 8/32 格灯纹理，以容量占比显示使用量；实际频道数由网络查询和 AE2 诊断工具读取。
- 物品模型直接以 AE2 对应颜色、对应种类的物品模型为父级，世界内也使用原部件渲染，不复制或修改 AE2 贴图。
- 新增线缆使用本附属的分等级标签，不并入 AE2 原配方的线缆标签，避免被原配方洗色为二级或产生材料转换漏洞。整合包可按等级使用 `ae2_cable_tiers:<种类>_tier_1` / `_tier_3` 标签。

由于需要对 AE2 内部频道节点及重染色逻辑做小范围 Mixin，目前依赖精确限定为已检查源码的 **19.2.18**。其他 AE2 版本需重新检查内部接口。与同时改写 AE2 核心频道算法的其他模组不能预先保证兼容，需要组合验证。

## 配置

NeoForge 服务器配置为世界的 `serverconfig/ae2_cable_tiers-server.toml`，服务器负责同步给客户端。默认值：

```toml
[channels]
basicTier1 = 4
basicTier3 = 16
denseTier1 = 16
denseTier3 = 64
```

编辑后重启世界/服务器。二级始终沿用 AE2 本身，不用附属配置覆盖；AE2 模式倍率另行作用。

## 构建与验证

需要完整 JDK 21 和网络可访问 NeoForge 官方 Maven、Maven Central、Gradle、Mojang 游戏资源。项目内有固定 Gradle 8.12 的 Wrapper 和发行包 SHA-256。

```powershell
.\gradlew.bat build
.\gradlew.bat runGameTestServer
```

Linux/macOS 使用 `./gradlew`。预期构建输出为 `build/libs/ae2-cable-tiers-1.0.0.jar`。构建成功后方可将其放进 NeoForge 实例的 `mods`，客户端和服务器都需要安装。不要把开发源码文件夹直接放入 `mods`。

可重复生成资源并检查：

```sh
python tools/generate_resources.py
python tools/validate_resources.py /path/to/appliedenergistics2-19.2.18.jar
```

第二条静态检查已实际通过：验证 255 个组合、170 个模型的 AE2 父资源引用、426 个配方、各色各类型的精确换算成本，以及不覆盖原版配方。

`src/gametest` 已准备真实 AE2 游戏测试：所有组合的节点容量及稀有度、六种实际频道上限、混合路径瓶颈、重染色和颜色隔离、倍率/无限模式、全部换算配方。因 NeoForge 依赖网络阻塞，目前没有执行这些测试，不能据此声称真实频道已验证。

开发缓存、测试世界和构建中间文件由 `.gitignore` 排除。测试代码不进入主模组 JAR。
